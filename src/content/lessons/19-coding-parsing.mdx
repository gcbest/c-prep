## Why this matters

Log and event processing is candidate-reported for Citi screens, and real risk systems ingest messy text. These problems test care more than cleverness: what happens with a blank line, extra spaces or a missing field.

## Core idea

**Parse defensively.** Decide for each line: valid, or skip. Never let one bad row crash the batch (and say you would count or log skipped rows in production).

- **`split` pitfalls:** `"a  b".split(" ")` yields an empty string between the spaces. Use `trim()` then `split(/\s+/)`. `"".split(",")` gives `[""]`, not `[]`. Split on the *first* space only when the rest is free text (`line.indexOf(" ")` plus `slice`).
- **Numbers:** `Number("")` is `0` and `Number("12abc")` is `NaN`. Check `Number.isFinite`, and reject empty strings explicitly.
- **Regex vs manual:** a regex is compact for a fixed shape (`/^\d{1,3}$/`) but easy to get subtly wrong (unanchored, `\d` matches only ASCII digits in JS but `Number` accepts `" 12 "`). Manual splitting is clearer for IPs. Say which you chose and why.
- **Sorting with several keys:** write the comparator as "first difference wins", and know whether your language's sort is stable (JS and Python are).

<Bridge from="Python" breaks="JS split(' ') keeps empty strings and has no maxsplit, unlike Python's split() and split(' ', 1).">
Python `line.split(None, 1)` is the same job as `indexOf(' ')` plus `slice` in JS.
</Bridge>

## Example

Total by category, ignoring malformed lines, and the letter-log comparator from LeetCode 937:

```ts
function totals(lines: string[]): Record<string, number> {
  const out: Record<string, number> = {};
  for (const line of lines) {
    const parts = line.trim().split(/\s+/);
    if (parts.length !== 3) continue;              // blank or malformed
    const amount = Number(parts[2]);
    if (!Number.isFinite(amount)) continue;
    out[parts[1]] = (out[parts[1]] ?? 0) + amount;
  }
  return out;
}

function reorder(logs: string[]): string[] {
  const body = (l: string) => l.slice(l.indexOf(' ') + 1);
  const isDigit = (l: string) => /^\d/.test(body(l));
  const letters = logs.filter((l) => !isDigit(l)).sort((a, b) =>
    body(a) < body(b) ? -1 : body(a) > body(b) ? 1 : a < b ? -1 : a > b ? 1 : 0);
  return [...letters, ...logs.filter(isDigit)];   // digit-logs keep original order
}
```

IPv4 validation: split on `.`, require exactly 4 parts, each all digits, no leading zero unless the part is `"0"`, value at most 255. IPv6: split on `:`, exactly 8 groups of 1-4 hex digits.

<Collapsible>
- **Leading zeros in IPv4:** `"01"` is invalid but `"0"` is valid. `"1.1.1.1."` has an empty fifth part.
- **Case:** IPv6 hex digits can be upper or lower case.
- **Floating point money:** summing decimals as floats drifts; use integer minor units in real systems.
- **Streaming:** for huge files, process line by line instead of loading everything.
</Collapsible>

<CheatSheet>

- Trim, then split on `/\s+/`; blank lines give empty or one-item arrays.
- Validate fields: count, `Number.isFinite`, ranges.
- Skip bad rows, never crash, and say you would count them.
- Regex for fixed shapes, manual split when clarity wins; anchor regexes.
- Comparators: first difference wins; digit-logs stay in original order.

</CheatSheet>
